# Contract: `remo-terminal.v1` Control Frames (separately versioned)

**Feature**: `020-openapi-type-generation` | **Status**: normative | **Protocol version**: `remo-terminal.v1`

Per FR-025, the terminal control frames are published as their **own** versioned artifact, deliberately
kept out of the REST OpenAPI document. This document supersedes the frame section of
`specs/010-web-session-interface/contracts/terminal-websocket.md` as the *machine-checked* source;
that document remains authoritative for handshake, backpressure, and close-code behavior.

---

## 1. Why separate

- The WebSocket route does not appear in the OpenAPI document at all — verified: the app publishes
  only `delete` for `/api/v1/terminals/{terminal_id}`.
- Folding the frames into `components` would put schemas in a REST document that no path references.
- The frame protocol versions on its own cadence (`v1` in the payload, `remo-terminal.v1` in the WS
  subprotocol) and must not be coupled to REST-surface evolution (FR-023).

---

## 2. Frames

Every frame is JSON text (binary frames are PTY data and are never control frames) and carries
`v: 1` plus a `type` discriminator.

### Browser → service

| `type` | Fields | Notes |
|---|---|---|
| `resize` | `cols: int`, `rows: int` | Clamped to safe bounds by existing logic before `TIOCSWINSZ` |
| `ping` | — | Keepalive; also drives the console's RTT measurement |

### Service → browser

| `type` | Fields | Notes |
|---|---|---|
| `ready` | — | PTY + ssh up |
| `exit` | `code: int` | Remote/ssh process ended |
| `error` | `class: ErrorClass`, `message: str` | `message` must stay human-safe and secret-free |
| `pong` | — | Reply to `ping` |

**`ErrorClass`** (closed): `auth` | `network` | `remote_capability` | `missing_project` | `remote_launch`

---

## 3. Normative rules

- **F-1 (single definition, FR-021)**: the frame shapes are defined once, on the service side
  (`src/remo_cli/web/frames.py`). The published artifact and the console's types both derive from it.
- **F-2 (the service uses its own definition, FR-021a)**: the service MUST construct and parse frames
  through these models. Ad-hoc dictionary literals in the WebSocket path are prohibited; SC-012
  requires zero of them (down from 5).
- **F-3 (lenient inbound, FR-024)**: an inbound frame that is malformed JSON, not an object, or of an
  unknown `type` MUST be **silently ignored** — exactly as today. Validation MUST NOT raise, and MUST
  NOT close the socket. This is the one place the refactor could change observable behavior.
- **F-4 (unchanged outbound bytes)**: serialized outbound frames MUST be byte-identical to today's
  `json.dumps` output for the same logical frame — key order included, since the console parses by key
  but tests may assert on strings.
- **F-5 (explicit version, FR-023)**: the artifact carries `protocol: "remo-terminal.v1"` and the
  in-frame `v: 1`. A change to either is a visible artifact change.
- **F-6 (independent versioning)**: the frame contract's version is documented as evolving
  independently of the REST contract. A REST change never forces a frame version bump, or vice versa.

## 4. Artifact

`frontend/src/api/generated/terminal-frames.json`:

```json
{
  "protocol": "remo-terminal.v1",
  "frame_version": 1,
  "inbound":  { "...JSON Schema for the browser→service discriminated union..." },
  "outbound": { "...JSON Schema for the service→browser discriminated union..." }
}
```

Generated by Pydantic's `TypeAdapter(...).json_schema()`, serialized with the same determinism rules
as the REST artifact (drift-checks contract §2 R-5).

---

## 5. Behavior that must not change (FR-024)

Re-sourcing the frame types must leave all of this untouched, verified by the existing terminal tests
passing unmodified:

- Bounded auto-reconnect budget and backoff schedule (3 attempts; 500/1500/3500 ms).
- Ping interval and the ping→pong RTT reporting path.
- Close-code handling (1000 / 1008 / 1011 / 1013).
- Binary-vs-text framing: binary is PTY data, text is control.
- Silent-drop behavior for malformed inbound frames (F-3).
